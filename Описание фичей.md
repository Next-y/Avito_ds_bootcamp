# Описание признаков финальной модели

В `solution.ipynb` используется **222 признака: 199 признаков самой cookie и 23 признака общих объявлений**. Ниже перечислены именно столбцы финальной модели. Из них 5 категориальных и 217 числовых. Этот файл дополняет ноутбук и не нужен для выполнения кода.

## Общие правила расчёта

- Одна строка соответствует одной cookie и её суточному окну.
- События фильтруются по `window_start_ts ≤ event_ts < window_end_ts`. Полные дубликаты исходных строк удаляются, события внутри cookie сортируются по времени.
- Разные события с одинаковым timestamp сохраняются. Неизвестный порядок таких событий не используется для построения переходов.
- Отношение с нулевым знаменателем остаётся `NaN`. Пустой набор для статистик и энтропии также даёт `NaN`; счётчики наблюдений равны нулю.
- `mean`, `median`, `min`, `max` — среднее, медиана, минимум и максимум. `std` — стандартное отклонение с `ddof=0` (для одного наблюдения равно нулю). `p25`, `p75`, `p90` — соответствующие процентили, вычисленные `numpy.quantile` с настройками по умолчанию.
- Энтропия: `H = −Σ pᵢ log₂(pᵢ)`, где pᵢ — доля соответствующего значения. `top_share` — доля самого частого значения.
- Числовые пропуски обрабатывают CatBoost и LightGBM. Категориальные признаки для CatBoost передаются строками; словарь категорий LightGBM строится только на обучающей части. Неизвестная категория LightGBM становится пропуском.
- `cookie_id`, буквальные значения `item_id`, тексты запросов, исходные строки UA и абсолютные даты не передаются модели как отдельные предикторы. Идентификаторы объектов используются для подсчётов разнообразия и совпадений.

## Как устроены признаки общих объявлений

Для каждого контекста вычисляется отдельный набор признаков. Обозначения:

- **A** — множество непустых `item_id` из `item_view` текущей cookie.
- **B(j)** — такой же набор другой cookie j в выбранном временном контексте.
- **N** — число других cookie с непустым B(j). Текущая cookie исключается.
- **c(a)** — число этих других cookie, смотревших объявление a. Повторы просмотров одной cookie не увеличивают число голосов.
- **k(j)** — число объявлений в пересечении A и B(j).

Расчёт выполняется на момент окончания окна t. События других наблюдаемых cookie за текущие и предыдущие сутки доступны пакетно, включая неразмеченные события validation/test. Их `target` не используется; будущие окна исключены. Контексты текущих суток и истории считаются отдельно.

Если N = 0, все частоты и признаки пересечения равны `NaN`; индикатор наличия истории равен 0. При N > 0 и непустом A отсутствие совпадений даёт нулевые частоты. Если A пусто, частоты собственных объявлений, `max_own_overlap_fraction` и Жаккар равны `NaN`, а число/доли соседей с пересечением при N > 0 равны 0. Для Жаккара действуют дополнительные условия поддержки, указанные в его определении.

Число собственных объявлений уже содержится в `diversity__viewed_item_nunique`, поэтому его дубли из новых признаков исключены. Индикатор `same_day__ref_available` был константой на обучающих частях и тоже исключён. В итоге осталось 12 признаков истории и 11 признаков текущих суток.

## Почему выбраны эти группы

Собственные признаки описывают объём, ритм и разнообразие действий, а признаки общих объявлений — сходство просмотров разных cookie. Совпадение само по себе не задаёт метку бота: связь признаков с target изучает модель.

Отдельный блок характеристик поисковых запросов и страниц выдачи исключён после сравнения на временной валидации. Счётчики поисковых действий и переходы с ними остаются. Из новых кросс-признаков сохранены только общие объявления; кросс-признаки запросов и UA в финальную модель не вошли.

Частоты и пересечения описывают наблюдаемую выборку, а не всю площадку. При изменении охвата и состава трафика их распределения могут измениться.
